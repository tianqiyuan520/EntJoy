## 四、v2 → v3 关键修正

| 修正项 | v2 设计 | v3 修正 | 原因 |
|--------|---------|---------|------|
| Shared Component | 同 Archetype 共享 `Dictionary<int, object>` | 值不同则拆 Archetype | v2 语义与 SoA 模型冲突 |
| TempAllocator | 完整 per-thread 栈 | 1.1a 去全局锁 | 收益/风险比低 |
| ChunkPool key | `(size, typeHash)` | canonical archetype identity | 哈希碰撞导致错误布局复用 |
| 实施顺序 | Phase 1→2→3→4→5→6→7→8→9 | Phase 1→3→4→2→5→6→7→8→9 | 先性能核心再存储增强 |
| Phase 9 | 与其他 Phase 混合 | 独立轨道 | 必须先建生命周期协议 |

## 九、已知限制与设计取舍

| 限制 | 说明 | 影响 |
|------|------|------|
| 循环依赖不检测 | 依赖图必须是无环 DAG，Complete() 不做环检测 | 死锁风险（文档化） |
| JobCostCache 哈希碰撞 | 256 槽位，>256 种 Job 类型时碰撞 | 仅影响 tile 数计算 |
| StealTop 有限重试 | 4 次重试 | 极高并发可能降低成功率 |
| AutoSIMD 不支持 ECS 调度 | IJobChunk/IJobEntity 暂不参与 | 用户需手动标后端 |
| AutoSIMD 不支持 long | int64 类型不支持 | 重算必须用 int/uint |
| SLEEF 精度 ~3.5 ULP | 非 IEEE 精确 | 追求精确结果需 SIMD_MATH_PRECISION=2 |
| Unity Burst S5 极快 | 0.016ms（Burst SIMD + 零 P/Invoke） | 编译器代数简化，非调度差距 |
