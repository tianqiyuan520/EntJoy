# 与参考实现的对照

以 Arch / EnTT / Flecs / Unity DOTS 的公开做法为基准，逐条路径核对 EntJoy 的设计是否偏离，以及偏离处的代价。数字全部来自本仓对照工程（`tools/EcsComparison`，10 万实体，`--ab-pair` 同进程交替、取轮内最小值）。

## 块遍历

参考实现都是两级结构：匹配到的原型（表）列表，每个原型一段连续的块数组；每块给列指针，循环体由调用方写。Arch 是 `query.GetChunkIterator()` + `chunk.GetSpan<T>()`，EnTT 是 `pool.begin()`，Flecs 是 `ecs_query_next` + `ecs_field`，DOTS 是 `ArchetypeChunk` + `GetNativeArray`。

EntJoy 同构：`Chunks()` 按原型列表推进，`QueryChunk.Span<T>()` 给列视图。块级过滤（shared / changed）在进入结果前判定；逐实体过滤不在块视图里表达，构造时直接拒绝。

读数：两组件 28.0–30.2 µs，Arch 27.0–27.3 µs。**已对齐。**

## 实体遍历

参考实现的实体遍历都是**回调形态**：Arch 的 `InlineQuery`、EnTT 的 `each(fn)` 把 `ref` 直接交给调用方，循环体里没有逐实体结果对象；DOTS 的 `SystemAPI.Query` 由源生成器展开成块循环，同样不构造结果。

EntJoy 的 `foreach` 必须每实体产出一个结果结构体，再经属性取 `ref`——这是 C# `foreach` 语法决定的形态，Arch 干脆不提供这个语法。逐条消融证明差额不在校验（去掉逐访问校验只回收约 5%），而在形态本身：86–90 µs 对 Arch 45–50 µs（1.85 倍）。

回调形态已补上：`IEntityForEach<T0,T1>`（结构体实现，JIT 按具体类型内联）配 `ChunkEnumerable<...>.ForEach`，循环体在块循环里原地展开，不构造结果。10 万两组件 49.8 µs，对 Arch `InlineQuery` 108.3 µs 快 2.2 倍、对自家 `foreach` 181.4 µs 快 3.8 倍；三组件 73.1 µs 对 129.0 µs 快 1.8 倍。arity 由 chunk 查询生成器按元组展开。

**结论：`foreach` 形态保持原样（可读性优先），吞吐路径用块遍历或回调。**

## 结构变更

参考实现都是「迁移到目标原型 → 复制各列 → 老块交换移除」。EntJoy 同形，且各项已在同一水平或略优：创建 1.02、添加 0.92、移除 0.84、销毁 0.88（相对 Arch）。

**已对齐。**

已知缺口：**关系组件**的结构变更（移除后重新添加）比普通组件同样的操作慢 3.1–3.9 倍。这不是规模问题——`--relation-churn` 逐实体成对执行，ns/op 在 2 千 / 8 千 / 3.2 万 / 10 万实体下为 441–446 / 472–475 / 553–556 / 656–730（`DOTNET_TieredCompilation=0`，按轮取最小），抬升只来自缓存缺失。差额来自关系路径每对操作额外的反向索引维护（`RelationIndex` 每次增删各一次哈希集合操作）、目标存活校验与关系版本推进；把索引增删整体短路后同样的四档为 384.7 / 389.9 / 421.2 / 506.5，即索引占 57–224 ns（13–31%），其余是每对操作的目标校验、关系值读写与版本推进。块选择与块地址回查都不是差额来源：`PrepareRelationSlot` 从块列表尾部起扫，稳态下第一个块就有空位；块下标在同一处一并交出，`AddToPreparedChunk` 先用它命中，对不上才按地址回查。

## 随机访问

参考实现在**句柄层面校验一次**（Arch 的 `Exists`、DOTS 的版本检查），之后取组件直接按已知下标算地址，不做逐次处置检查与越界检查。

EntJoy 原先在同一件事上查了两遍：入口校验过实体句柄后，取组件又查了一遍块的处置状态、实体下标与列下标。改为句柄校验一次后直算地址（关系列只读判据保留，那是语义）。

读数：读 425–439 µs / 1.14–1.18 倍；写 1588–1656 µs / 1.36–1.45 倍。写路径的剩余差额来自变更位标记与观察者判定，参考实现没有这两项。

同一条规则的其它落点：`SetSharedComponent<T>` / `GetSharedComponent<T>` 原先按 `Type` 走装箱读写，落值还要 `GCHandle.Alloc(Pinned)` + `MemoryCopy`；类型已知时改为按 `T` 直接读比较与就地写。两条单实体写入入口也收敛到一条：`SetComponent<T>` 的非关系分支转调 `Set<T>`，关系分支保留自己的写入（要维护反向索引）。

**已对齐。**

## 变更过滤

DOTS 的 `WithChangeFilter<T>()` 是块级过滤：整块里任意实体被改过，整块都进来，精确到实体由调用方再判。EntJoy 的 `WithChanged<T>()` 同义，同样挂在查询链上。

读数（同一世界内配对）：所有块都脏 78.9–79.8 µs，为不过滤的 1.02 倍；所有块都干净 1.1 µs，为 0.013 倍。

**已对齐。**

## 启用位过滤

DOTS 在块级维护 `EnabledMask`，逐实体掩码由调用方处理；EntJoy 在块级位图上做段扫描，连续置位段整段交出，语义等价且更省调用。

成本已对齐：全启用时 110.1–110.8 µs，为同世界不过滤的 1.08 倍。游标按 64 位字推进，整字全置位时区间跨字延伸到下一个未启用位，全启用块与不过滤一样一次交出整块，只剩每块一次位图判定。

**已对齐。**
