# ECS Chunk 缓存布局

Chunk 将 Entity 和各组件分别存为连续列。每列内部的实体顺序不变，列起点按缓存行对齐；相邻非空列的起点在缓存检测周期内位置相同时，下一列增加一条缓存行的间隔。Entity 列起点参与第一次比较。

## 参数来源与默认值

布局参数在进程中首次使用时读取一次，此后固定：

| 参数 | 确定方式 | 默认值 |
|---|---|---:|
| 缓存行大小 `L` | Windows `GetLogicalProcessorInformationEx(RelationCache)` 报告的 L1 Data/Unified 缓存行大小；多个核心取最大有效值 | 64 字节 |
| 检测周期 `P` | 各 L1 Data/Unified 缓存的 `CacheSize / Associativity`；各缓存报告的周期一致时采用该值 | 4096 字节 |

非 Windows 平台、系统接口不可用或无有效记录时使用默认值。相联度未知、完全相联或核心间周期不一致时，周期使用默认值，并保留有效的缓存行大小。

有效缓存行大小是 16 至 65536 字节之间的 2 的幂，保证其整除 slab 的 64 KiB 对齐。有效周期大于缓存行大小，且是其整数倍；组合不满足条件时，两个参数均使用默认值。

`P` 是用于列布局的缓存地址模式检测周期，独立于操作系统页大小。它支持非 2 的幂，例如 48 KiB、8 路缓存对应 6144 字节。该规则采用常见组相联缓存的索引模型，不推断 CPU 的地址哈希或地址别名机制。

## 分页、缓存行与缓存组

操作系统通过页表，把进程的虚拟地址映射到物理内存。常见页大小为 4096 字节；具体页大小及大页配置由平台决定。页内偏移在地址转换前后保持不变。分页负责地址映射和内存管理。

CPU 缓存保存内存数据的副本。数据以缓存行为单位传入缓存，例如读取一个 4 字节整数，CPU 可能同时取得其所在的 64 字节缓存行。缓存命中表示所需数据已在缓存中；缓存未命中表示需要向更低级缓存或内存取数据。缓存未命中与操作系统缺页是不同事件。

组相联缓存分成多个组，每组有若干个槽位，槽位数量称为相联度。缓存行只能进入地址映射到的组，组内的地址标签区分不同内存数据。组满时，新数据需要替换已有数据。

在简单按地址索引的模型中：

```text
缓存组数量 = 缓存容量 / (缓存行大小 × 相联度)
组编号     = floor(地址 / 缓存行大小) % 缓存组数量
重复周期 P = 缓存组数量 × 缓存行大小 = 缓存容量 / 相联度
```

例如 32 KiB、64 字节缓存行、8 路缓存，有 64 个组，每组 8 条缓存行，组索引每 4096 字节重复。不同列相隔 4096 字节的整数倍时，相同元素附近的数据可能进入相同组。

## 间隔如何分散缓存组

用一个便于演示的小缓存：容量 512 字节，缓存行 64 字节，每组 2 路。因此共有 4 组，重复周期为 256 字节。假设三个组件列各占 256 字节，下面只观察各列的第一条缓存行：

| 列 | 连续排放的地址 | 组编号 | 列间留 64 字节后的地址 | 组编号 |
|---|---:|---:|---:|---:|
| A | 4096 | 0 | 4096 | 0 |
| B | 4352 | 0 | 4416 | 1 |
| C | 4608 | 0 | 4736 | 2 |

连续排放时，三条缓存行争用组 0 的两个槽位。反复访问 `A、B、C、A、B、C`，在 LRU 替换模型下每次访问都会挤出下一轮需要的数据。留出间隔后，三条缓存行分别进入组 0、1、2；装入后再次访问可命中。真实 CPU 的替换和预取策略由硬件决定。

间隔改变的是地址到缓存组的映射，组件值及读写语义保持不变。两个列起点相差 `P` 的整数倍时，无论 Chunk 起点在页中何处，其对 `P` 取余的位置都相同；判断不要求 Chunk 位于页首。

## 分配与容量

slab 起点按 64 KiB 对齐。Chunk stride 覆盖 `ChunkMetadata.TotalSize` 并向上对齐到 `L`，使 slab 内每个 Chunk 的底地址均满足缓存行对齐。组件列、变更位图和 shared 区采用相同的缓存行对齐参数。

自动容量以 16 KiB 为目标，按完整布局核算列间隔、位图和 shared 区。默认最多容纳 128 个实体，与 Unity 的普通 Chunk 上限一致；较大的组件可使容量降为 64。实体容量以 64 个实体为粒度，最少为 64；该粒度用于位图遍历，与缓存行字节数独立。默认容量为二次幂，`NativeColumn<T>` 的跨块定位采用移位路径。最小容量所需布局可超过目标大小。显式 `ChunkCapacityOverride` 保持其指定容量，并按完整布局分配内存。

## 适用边界

`NativeColumn<T>` 提供非拥有的全局索引视图，支持固定容量的多 Chunk 列和末尾部分块。视图持有列指针表，数据及指针表由调用方拥有；地址、块顺序和容量在使用期间保持稳定，结构变化后重建视图。`GetElementPtr(i)` 解析单个元素，`CopyTo` 用于显式快照发布。多块视图的 `GetUnsafePtr()` 抛出异常。NativeTranspiler 当前支持其 C++ 标量作业字段、索引访问和 `GetElementPtr`；其他后端或自动 SIMD 配置报 NT033。

规则只分散相邻非空列的起点。非相邻列、不同组件大小造成的后续访问，以及其他活跃数据仍可能争用缓存组。物理地址参与索引且检测周期超出页内偏移范围时，虚拟地址取余也无法精确推断实际缓存组。实际收益取决于访问顺序、活跃缓存行数量、预取、替换策略与 CPU 索引方式。64/4096 是信息不足时的默认策略；硬件参数驱动的布局仍需要在目标负载上验证收益。
