## 二、当前遗留问题

### 问题 1：SourceGenerator 生成代码编译错误（72 个 CS1929/CS1061/CS1729）

**现象**：SourceGenerator 为所有 IJobEntity（含 `[NativeTranspile]`）生成了适配器代码，但生成的代码编译失败。

**错误分布**：
- CS1929：44 个（"不包含定义"）
- CS1061：32 个（"does not contain a definition for"）
- CS1729：32 个（参数数量不匹配）

**全部来自 `.g.cs` 生成文件**（`samples/EntJoySample/obj/Release/EntJoy.ECS.SourceGenerator/...`），样例源码本身无错误。

**根因分析**：
适配器生成了 `Schedule`/`ScheduleWithWorkerCap`/`Run` 方法，调用 `NativeEcsScheduler.ScheduleChunk(ref this, ...)`。但：
1. 适配器是 `internal struct`（在 sample 程序集），而 `NativeEcsScheduler` 在 ECS 程序集——跨程序集 `ref` 传递可能有兼容性问题
2. 生成代码的 `using` 只有 `EntJoy` + `EntJoy.JobSystem`，可能缺少 `EntJoy.ECS` 命名空间中的类型解析
3. CS1061/CS1729 表明方法签名不匹配——需要进一步检查生成代码与 `NativeEcsScheduler.ScheduleChunk<T>` 的参数是否对齐

**需要的下一步**：
- 用 `EmitCompilerGeneratedFiles=true` 持久化生成文件，读取具体错误行
- 检查生成的 adapter 与 `NativeEcsScheduler.ScheduleChunk<T>(ref T, EntityManager, QueryBuilder, NativeJobHandle?)` 的签名匹配
- 可能需要在生成代码中加 `using EntJoy.ECS;`（如果 ECS 类型不在 `namespace EntJoy`）

### 问题 2：`EntJoyNativeDllDir` 配置 — 仅编译任务侧完成
- `NativeCompileTask` 已支持读取 `NativeDllDir` 属性
- `NativeTranspilerGenerator` 已支持读取 `build_property.EntJoyNativeDllDir`
- 两个 sample csproj 已配置 `<EntJoyNativeDllDir>` + `<CompilerVisibleProperty>`
- 但源生成器读取 `build_property` 的可行性需要验证（`AnalyzerConfigOptionsProvider` 机制在增量生成器中的正确用法）

### 问题 3：IJobChunk 类型的 Schedule 扩展方法
- `IJobChunk` 类型（`MoveJobChunkCpp`/`MoveJobChunkIspc`）没有 Schedule 扩展方法
- 这些类型由 NativeTranspiler 的 `BindingsGenerator` 处理（生成 `Schedule_CPPJob` 等绑定），不是 SourceGenerator
- 样例直接调用 `.Schedule(query)` 但没有对应扩展——是样例代码问题还是设计缺口需要确认

## 三、架构现状（当前代码结构）

```
EntJoy.Mathematics       ← 零依赖
EntJoy.Collections       → Mathematics
EntJoy.Jobs              → Collections（含 NativeJobCore 执行引擎，零 ECS）
EntJoy.ECS               → Collections + Jobs（NativeEcsScheduler chunk 调度）
EntJoy.ECS.SourceGenerator ← 为所有 IJobEntity 生成 C# Schedule 扩展 + IJobChunk 适配器
NativeTranspiler         ← 只翻译 C++/ISPC（不生成 C# 调度代码）
```
