## 4. 方法学：本批如何保证"只动注释"

`comment_guard.ps1`（游戏仓 `logs_stack10\` 下）—— 对每个改动文件，用**两个独立实现**
（状态机跳过字符串/字符字面量 + 朴素正则）剥离注释后逐行比对旧/新内容，任一不同即 FAIL 并报出差异行。
脚本自检：只加一行注释 ⇒ PASS；改一个代码 token（`JobHandle` → `JobHandleX`）⇒ FAIL 且定位到差异行。
最终 6 个改动文件 **ALL PASS**。

同时踩到/修掉的三个副作用（供后续同类清理参考）：
1. 用 `WriteAllText` 批量写回会**顺手剥掉 BOM**、并可能归一化换行符 ⇒ 必须只写真正改过的文件，写完复查编码。
2. 正则 `原为` 会**误匹配**"还**原为**"。
3. `[System.IO.File]::ReadAllLines('相对路径')` **不走 PowerShell 的 CWD**（按进程 CWD 解析）⇒ 脚本一律用绝对路径。

⚠ **校验器自身的已知误报模式**：状态机实现把 `'` 当字符字面量起点，若文件里存在**不配对的单引号**
（例如出现在注释里的撇号），此后所有注释都不再被剥离 ⇒ 该文件会被判 FAIL。
实例：`src/NativeDll/JobSystemInternal.h`（`'` 计数为 1）在有注释改动时报了 FAIL，
用朴素的 `//.*$` 实现与逐行 `git diff` 复核后确认为误报。
⇒ 判 FAIL 时**必须**再用朴素实现 + `git diff -U0` 人工确认，不能直接回退。
