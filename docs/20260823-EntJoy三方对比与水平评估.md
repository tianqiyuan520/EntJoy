## 二、S5 的问题、S6 与 AutoSIMD

### S5 高竞争失真
Clang `/O2` 把 `sum += index * j` 闭式替换为 `index * 499500`（汇编仅 `imul eax, ecx, 499500; ret`）。**Cpp S5 = 0.053ms 是作弊**，不代表真实计算。

### S6 控制流+重运算（编译器无法作弊）
LCG 伪随机 + 数据依赖分支，编译器**无法**代数简化/闭式替换：
```csharp
for (int j = 0; j < 1000; j++) {
    x = x * 1664525u + 1013904223u;   // 链式状态依赖 → 无法闭式
    uint r = x % 13u;
    if (r < 4u) sum += x;  else if (r < 8u) sum ^= x;  else sum -= (x>>3);
    if ((x & 7u) == 0u) sum += j;
}
```

### AutoSIMD（C++ 自动 SIMD 向量化）
通过 `[NativeTranspile(AutoSIMD = Enabled)]` 标记，NativeTranspiler 生成 SIMD 内联代码（AVX2 intrinsics），C++ 代码自动享受 SIMD + 循环优化：
- **S5 AutoSIMD = 0.620ms ≈ ISPC 0.611ms**（同级！验证 AutoSIMD 能达到 ISPC 性能）
- S6 AutoSIMD：transpiler 对 uint 模运算 `x % 13u` 生成了 `simd_value<int>→simd_value<float>` 类型不匹配（待修 SimdValue.h + transpiler）

## 五、关键发现

1. **调度器质量**：EntJoy Native S4=0.000ms 全库第一；4/5 C++ 场景胜 TBB/OpenMP。
2. **执行引擎**：标量 Cpp ≈ Managed/ZeroAlloc（~40ms）；只有 SIMD 是真差距。
3. **AutoSIMD 胜 ISPC 1.66x**：S6 AutoSIMD 3.30ms = ISPC 5.48ms → save-modify-blend 正确选择分支，Clang 对 AutoSIMD C++ 进一步优化（循环展开、lane 合并、代数简化）。
4. **S5 噪声**：Cpp 0.058ms 是编译器闭式替换；S6 是公平场景。
5. **调度开销定性**：纯 C++ S4=0.000ms 证实调度本身极快。
6. **ISPC Unity 绑定修复**：S6 ISPC Unity 修复前 56ms（托管标量）→ 修复后 5.5ms（原生 ISPC）。根因是 bindings.g.cs 缺少 S6 Ctrl 的专属 Schedule 重载，`.Schedule()` 回落泛型托管回调。修复后 ISPC Unity/tools 比值 = 1.0x。
7. **S5 Cpp 输给 UnityB 不是 SIMD 差距**：Cpp 计算（0.005ms）比 Burst（~0.005ms）快或持平。Cpp 输在 EntJoy 调度链固定开销（0.045ms），不是计算。
8. **UnityB 调度并不轻量**：S4 调度延迟 UnityB=0.019ms > Managed=0.002ms。UnityB 在 S5/S2 赢是因为 Burst SIMD 计算优势，不是调度优势。
9. **调度开销精确定位**（2026-08-23 profiling）：S5 Cpp tiled 调度开销 0.045ms 中 ~70% 是 `notify_all()` 唤醒 15 workers（futex + 上下文切换）。SubmitBatch dispatch：2w→5μs / 13w→13μs / 15w→30-35μs，**由参与 worker 数主导，非 tile 数**。优化方向 = 加快唤醒（延长自旋 / eventcount），非降 worker 数。

### JobCostCache（per-job 自动 batch，export flag 默认关闭）

- 256 槽无锁 EWMA（Q22 定点 + FNV-1a funcHash，碰撞重学，CAS 防并发丢更新）
- ResolveChunkSize：`tiles = clamp(totalUs/150μs, 1, wc×16)` + `kMaxAutoChunk=32k` 元素护栏
  （防大 job 塌缩成串行巨型 tile，实测 S3 曾 0.074→0.164 回归后修复）
- 双向 α=0.75、无上升阻尼：成本波动（同 job 依赖外部参数 10↔10000 次循环）1-2 轮跟随；
  单次 GC/抢占尖峰自愈（下溢修复后不再需要 4x 升限）
- 热路径 <3ns；flag 关闭零开销

### 自适应自旋（WorkerLoop park 段）

- 保持 wake-all 语义（选择性唤醒有 35ms 尖峰教训）
