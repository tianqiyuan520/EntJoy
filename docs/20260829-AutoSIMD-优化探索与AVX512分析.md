## 二、AVX512 探索结论

### 2.1 已完成

- `NativeSIMD.h`/`SimdValue.h`/`NativeSIMD_math.h` ~75 函数 AVX512 分支（`__m512`/`__mmask16`，16-wide）
- 16-wide 数学多项式 `_n_sin_avx512`/`_n_cos_avx512`/`_n_log_avx512`（平移自 AVX2 版）
- `simd_mask::all_true()` AVX512 分支（`(n_mask)0xFFFF`，修复 C05/C12 全错）
- gather 按 clang 参数顺序 `(index, addr, scale)` 修正（MSVC 相反）

### 2.2 性能结论（N=1M，Zen 4 双 256-bit datapath，3 轮中位）

| Case | AVX2 | AVX512 | 效果 |
|------|------|--------|------|
| C02 sin/cos×16 | 23.4ms | 13.7ms | **快 1.7x**（此前逐 lane fallback 136ms） |
| C01 纯算术 | 0.350 | 0.319 | 快 10% |
| C05 while | 2.66 | 2.35 | 快 12% |
| C08 int LCG | 274 | 243 | 快 13% |
| C06/C07/C10 | — | — | 持平 |

**结论：Zen 4 上 AVX512 收益 10~70%（数学密集最高），非 Intel 的 2x。**

### 2.3 重要修正：C08 "ISel 爆炸"是误判

- 一度以为 C08（1000 次循环大函数）AVX512 编译触发 LLVM X86 DAG ISel 组合爆炸（20+ 分钟），用 `-opt-bisect` 定位 pass #2141，并用 `-mllvm -fast-isel` 绕过。
- **修正**：重新验证发现 C08 正常 `/O2` 编译只需 **0.5s**（有/无 pragma 都 0.5s），运行 PASS 238ms。之前的"卡"是误判或环境问题，**fast-isel 不需要**。
- fast-isel 实测**损失性能**（C07 慢 16%），应彻底弃用。

### 2.4 是否接入多版本 dispatch

- **不建议全量多份编译**（浪费编译时间/体积）。
- 正确做法：clang `__attribute__((target_clones("avx2","avx512f")))` 单源码多版本 + ifunc dispatch；或只 2 版（AVX512+AVX2，跳过 SSE2）。
- 更根本：Zen 4 收益仅 10~70%，**默认只 AVX2、AVX512 作可选**可能更务实。

## 三、C11/C12 慢 ISPC ~40% 的根因（汇编级）

### 3.1 现象

C11（while 生命周期）、C12（查找+continue）稳定慢 ISPC ~40%（Auto/ISPC ≈ 0.5x）。C05（while+break）慢 ~17%。

> **2026-08-30 更新**：方向2（uniform 条件标量化，commit `57d1f68`）落地后 **C11 已反超 ISPC**（Auto/ISPC ≈ 1.29–1.72x），本节的"C11 慢 ~40%"已过时。C12 仍落后，见 §七/§八。

### 3.2 根因：float mask vs int mask 的代码生成差异

对比 while 循环体每轮指令：

| | 关键指令 |
|---|---|
| **ISPC** | `vpcmpgtd`(int 比较) + `vpandn`(int and) + `vblendvps`，**无格式转换** |
| **AutoSIMD** | `vcmpltps`(float 比较) + `vpandn` + `vextracti128`+`vpackssdw`+`vpmovzxwd`+`vpslld`（**16 位打包/扩展 ~5 条**） |

AutoSIMD 的 `n_mask` 是 `__m256`（float 向量），比较用 `_mm256_cmp_ps`（float）。clang 对「float 比较 → and → blendv」链做 16 位打包优化（把 8 个 32 位 mask 压成 16 位再扩展回符号位），每轮多 ~5 条指令。ISPC 用 int 比较（`vpcmpgtd`）+ 直接 `vpandn`，无打包。

**关键约束**：float 的 `>` 比较不能用 int `>` 替代（float 与 int 对负数位序语义不同），所以 mask 的 float 表示是结构性的，需要显式改表示。

### 3.3 教训：变量分类的"过度优化"陷阱

曾尝试把 C11 的 `frames++`（无条件 +1）恢复为 uniform 标量，结果**更慢**（0.48x）：uniform 标量 `frames<16` 与 varying mask `energy>1` 合并时，clang 生成更多格式转换（`vpackssdw`+`vpmovzxwd`+`vpslld`）。**结论：变量在 while 体里应保持 varying（向 ISPC 靠拢），不要擅自改回 uniform。** 已回退。

## 四、如何继续对齐 ISPC

### 方向 1（已验证无效）：mask 表示从 float 改为 int

- **目标**：消除 clang 的 16 位打包（每轮 ~5 条）。
- **验证结果（2026-08-29 实测，两个子方案都无效）**：
  1. **int mask 化**（`n_mask` 改 `__m256i`、比较返回 `_mm256_castps_si256`、and 用 `_mm256_and_si256`）→ 编译通过但 `vpackssdw`/`vpmovzxwd`/`vpslld` **仍在**，汇编几乎不变。
  2. **算术 blend**（`a + (b-a)*(mask & 1.0f)` 替代 `_mm256_blendv_ps`）→ clang 识别出等价性，**又优化回 `vblendvps`**，无效。
- **深化根因**：`vpackssdw` 是 clang 对「while 循环里 mask 的**符号位提取 + 16 位打包跨循环传递**」的固有优化，与 mask 类型（int/float）、blend 实现（`vblendvps`/算术）、测试实现（`vtestps`/`vmovmskps`）都无关——三个子方案都验证无效，clang 都会优化回等价形式。
- **ISPC 为何成功**：ispc 编译器把 `.ispc` 源做 SPMD 转换，mask 是「单次比较的直接结果」，`vcmpltps → vblendvps → vmovmskps` 直接串联，**不经 clang 的 C++ 优化器**，故无 `vpackssdw`。而 AutoSIMD 生成 C++ 的 while-true + tracker + 多层 `and` + blend，clang 对这个 C++ mask 链做符号位打包。
- **编译器确认**：`NativeTranspiledPrecise.vcxproj` 的 `<PlatformToolset>ClangCL</PlatformToolset>`——实际就是 clang-cl 编译，非 MSVC。
- **结论**：NativeSIMD.h 层面走不通，需改生成器 while 循环结构（见方向 2 的 uniform 条件标量化）。方向 2 只对「uniform 条件」生效（mask 链变短）；纯 varying 条件（C12）mask 链长，clang 仍打包，属结构性代价。

### 方向 2：while 循环 uniform 条件标量化（唯一有希望的剩余方向）

- **问题**：C11 的 `while (energy > 1 && frames < 16)` 中，`frames < 16` 是 uniform（同步 +1），`energy > 1` 是 varying。当前翻译成 while-true + 每轮重算两个条件 + broadcast，触发 clang 的 mask 打包。
- **方案**：识别 while 条件的 uniform 子条件，生成「标量 while + varying tracker」：
  ```cpp
  int frames = 0;
  simd_mask tracker = all_true;                 // active lane（energy > 1）
  while (frames < 16 && tracker.any_true()) {   // 标量循环（uniform 上限）
      simd_mask cond = (energy > 1);            // varying 条件
      tracker = tracker & cond;                 // energy <= 1 的 lane 退出
      energy = blend(energy, energy * 0.9f, tracker);
      frames++;
  }
  ```
- **改动点**：`SimdControlFlowGenerator.GenerateWhileStatement`，需分析 while 条件 AST，分离 uniform/varying 子条件（`BinaryExpressionSyntax` 的 `&&` 树）。
- **复杂度**：中（~100 行生成器代码），需处理 `&&`/`||` 混合、多 uniform 子条件。
- **收益不确定**：可能消除 `vpackssdw`（若 clang 对新 mask 结构不打包），也可能 clang 仍打包。需实测验证。
- **风险**：中（改 while 翻译核心路径，需全量回归 C05/C11/C12）。

### 方向 3：while 循环展开（2x）

- 展开 2 次，每 2 轮做一次 mask 检查/`any_true`，摊薄水平归约开销。需处理提前退出（break），复杂度中，收益 ~10%。

### 方向 4（低优先）：any_true 用 `vtestps` 替代 `vmovmskps`

- 当前 `n_any_true` → `_mm256_testz_ps`（vtestps），已与 ISPC 一致，无明显优化空间。

### 建议顺序

1. **先做方向 1**（mask 表示 int 化）——根因明确、对齐 ISPC 的核心，预期 C11/C12 追平。
2. 方向 2/3 作为后续微调（收益小）。

## 五、FMA 融合根因与 fast-math 辨析

### 5.1 FMA 根因（C06/C09 慢 ISPC 的根因）

对比 C06（min 归约）主循环每轮（j 迭代）指令：

| | 每轮指令 | 说明 |
|---|---|---|
| ISPC | `vfmadd213ps`(A*const+B) + `vminps` = **2 条** | `--math-lib=fast` 隐含 FMA |
| AutoSIMD(旧) | `vmulps`(A*const) + `vaddps`(+B) + `vminps` = **3 条** | `/fp:precise` 禁止 FMA |

16 次迭代 → 32 vs 48 条，差 1/3，对应 42% 差距。**修复**：`NativeTranspiledPrecise` 加 `-ffp-contract=fast`，C06 0.58→0.91x、C09 0.76→0.87x。

> ⚠️ **2026-08-30 修正（推翻本节"修复"）**：实测 clang-cl 报 `warning: unknown argument ignored in clang-cl: '-ffp-contract=fast'`——CMakeLists 里裸写的这个 flag 对 clang-cl 是**空操作**。标量尾循环里的 `vfmadd213ss` 来自 clang 默认收缩，不是这个 flag；此前 SIMD 代码实际上**没有** FMA 契约。真正引入 SIMD FMA 的是 2026-08-30 生成器显式 `n_fmadd_ps`（见 §八）。故本节"C06/C09 因此改善"若在 clang-cl 上测出，需归因于同 commit 的其他改动或 gcc 风格 clang 工具链，建议复验。

### 5.2 为什么会有 NaN/±0 语义问题，而 ISPC 没有

`/fp:fast`（clang 的 `-ffast-math`）是**完整 fast-math**，破坏 IEEE 三类语义：

| fast-math 优化 | 例子 | NaN/±0 边界下 |
|---|---|---|
| 假设无 NaN/Inf | `x-x→0`、`x*0→0` | `NaN-NaN=NaN≠0`、`Inf*0=NaN≠0` |
| 忽略 ±0 符号 | `x+0→x` | `-0+0=+0≠-0` |
| 重排运算 | `(a+b)+c→a+(b+c)` | 浮点加法不结合，舍入改变 |

AutoSIMD 的**控制流条件**（`if(v<best)` min 归约、`if(x!=x)` NaN 检测、循环边界累加）依赖这些边界语义，所以 `/fp:fast` 让 EC2/EC8/E5 失败。

**ISPC 为什么没问题**：ISPC 用 `--math-lib=fast`（只近似数学函数 + 允许 FMA），**不是 `--fast-math`**（生成代码 `NativeTranspilerGenerator.cs` L365-367 确认：`mathLib==fast ? "" : " --opt=disable-fma"`，无 `--fast-math`）。ISPC 的控制流 mask 用硬件比较指令（`vcmpps`/`vpcmpgtd`）直接生成，硬件指令本身符合 IEEE，`--math-lib=fast` 不碰它们。

| | 数学函数 | 控制流 NaN/±0 | FMA |
|---|---|---|---|
| AutoSIMD 旧 `/fp:fast` | 近似 | ❌ 破坏（代数简化） | 允许 |
| ISPC `--math-lib=fast` | 近似 | ✅ 精确（硬件指令） | 允许 |
| AutoSIMD 现在 `/fp:precise`+`-ffp-contract=fast` | 精确(SLEEF) | ✅ 精确 | 允许 |

**结论**：`-ffp-contract=fast`（FMA 契约）是 IEEE 754 标准操作，只做 mul+add 融合成单次舍入，**不动控制流的 NaN/±0 语义**，与 ISPC 的"适度"一致，而非旧 `/fp:fast` 的"过度"。

### 5.3 验证结果

- EC1/EC2/EC8（NaN/±0/subnormal）**全 PASS**——FMA 契约没复发当初的问题。
- FZ5（nested if/else acc，`maxUlps=0` bit-exact）FAIL `nbad=2/1/12`，差异是最低位 1 bit（1 ULP），是 FMA 的正常舍入，被 bit-exact 过严比较捕获（对比 FZ1 用 `maxUlps=8`）。建议 FZ5 改 `maxUlps=1`。

## 七、C12 剩余差距深入分析（重新分析 + 待办，供新会话继续）

### 7.1 纠正：vpackssdw 是误导

之前把 C12 慢 50% 归因于 clang 的 `vpackssdw`（符号位打包），**是错的**。重新定位发现 `vpackssdw`/`vpmovzxwd`/`vpslld` 出现在**函数开头**（一次性构造「写回的 active lane mask」供 `vpmaskmovd`），**不是 while 循环体的每轮开销**。

### 7.2 已修复：写回 scatter + savedMask all_true 误判

C12 的 `R[i]=found`（int→float 写回）走了 per-lane scatter（逐 lane extract+标量 store），根因是 `inNarrowedContext` 判断（`_currentMask != "simd_mask::all_true()"`）**误判**：循环后 `_currentMask` 是 `__mask_1`（变量名），值其实是 all_true。

**修复**（commit `5f8c627` + 补全）：
1. `SimdExpressionTranslator` 的 contiguous store 优化加 int→float 转换（`n_store_ps + n_cvtepi32_ps`）。
2. `SimdLoopGenerator` 三处循环（`GenerateWhileStatement`/方向2标量化/`GenerateDoStatement`）记录 `savedMaskIsAllTrue`，循环后恢复为字面量 `simd_mask::all_true()`。

效果有限：C12 0.51x → 0.55x（写回只是次要开销）。

### 7.3 C12 剩余 45% 的真正构成（微架构，非单一 bug）

逐条汇编对比 while 循环体（各 ~22 条/轮，指令数几乎相同），差距是累积的小开销：

| 差异 | AutoSIMD | ISPC | 影响 |
|---|---|---|---|
| FMA | `vmulps+vaddps`（int→float 转换阻断融合） | `vfmadd231ps` | ~1 条/轮 |
| j<16 检查 | `vpbroadcastd 15`+`vpcmpgtd`+`vpandn`+`vtestps`（clang 反转循环引入） | `vmovmskps`+`cmpb`+`je` | ~1-2 条/轮 |
| B load | 非 masked（load 8 lane） | `vmaskmovps`（masked） | 带宽 |
| 分支 | 4 次 `vtestps`+分支 | 2 次 `vmovmskps`+`cmpb`+`je` | 分支预测 |

**关键**：这些是 clang 的代码生成行为（int→float 转换阻断 FMA 契约、循环计数器反转引入额外比较），不是生成器 bug。指令数相近却慢 45%，说明差距在**微架构**（分支预测、指令调度、内存访问模式），静态汇编已到极限。

### 7.4 待办（供新会话）

1. **FMA 融合优化（生成器层面）**：~~可做~~ **已于 2026-08-30 完成**（见 §八）。识别 `float*int+float` 模式 → 生成 `n_fmadd_ps(v_acc, n_cvtepi32_ps(v_j+1), B)`，回收 int→float 转换阻断的那 ~5%。当前生成代码 `v_acc * (v_j+1) + B` 的隐式转换（`simd_value<int>→float`）让 clang 不融合 FMA。**结果：汇编已由 `vmulps+vaddps` 变 `vfmadd213ps`，但 C12 实测无显著提升（~5% 淹没在基准噪声里）。**
2. **运行时 profile（定位 45%）**：`perf stat`（Linux）/ VTune（Windows）跑 C12，看 IPC / 分支预测 miss / 缓存 miss，确定微架构瓶颈。
3. **FZ5 测试过严**：FZ5 用 `maxUlps=0`（bit-exact），FMA 的 1 ULP 舍入被判 FAIL。建议改 `RunPair("FZ5", ..., maxUlps: 1)`（对齐 FZ1 的容差思想）。
4. **AVX512 可选接入**：已探明（~75 函数分支 + 数学多项式 + fast-isel 误判纠正），Zen 4 收益 10~70%，是否正式接入（target_clones 多版本）待决策。

### 8.3 基准降噪（2026-08-30 已完成 + 修正）

- **问题**：N=1M、0.1–0.5ms 量级的用例跨轮漂移 ~30%（如 C01 Auto/ISPC 三轮 0.89 / 3.36 / 0.93x），5% 级优化无法可靠测量。
- **方案（已落地，`Program.cs` 的 `MeasureMs`）**：保持 N=1M（缓存驻留），自校准把每个计时样本批量执行到 ~100ms（reps 上限 2000），取 7 样本中位数。C12 Auto/ISPC 5 轮 = 0.68 / 0.71 / 0.68 / 0.74 / 0.70，中位 **0.70**，**±4.3%**。
- **修正（原建议"把 n 提到 100M"是错的）**：实测 N=10M 时数组 40MB 超出 L3，测量被内存带宽/延迟主导——连标量 Cpp 都跟 SIMD 持平（C04 Cpp=5.89 甚至快于 ISPC=7.35），后端计算差异被完全掩盖。**增大 N 只测出公共瓶颈，测不出后端差异**；N 必须保持缓存驻留（1M/4MB）。
- **遗留**：C07（gather，缓存敏感）与 C01（0.05–0.25ms，固定开销主导）仍 ~±30% 噪声；若要测这两个用例需另做交错测量（三后端轮流测多轮取中位数）。
- **C12 结论**：中位 0.70x（Auto 比 ISPC 慢 ~1.43x），差距真实且稳定可测；FMA 修复未改变它（符合 §8.2 预期）。

### 8.4 修正：`-ffp-contract=fast` 被 clang-cl 忽略（推翻 §5.1）

- 实测 clang-cl 报 `unknown argument ignored: '-ffp-contract=fast'`，CMakeLists 裸写该 flag 是空操作。
- 若要启用 clang 自动 FMA 契约，正确写法是 `/clang:-ffp-contract=fast`（或 `-Xclang -ffp-contract=fast`），可覆盖 `a+b*c`、`a*b-c` 等本次显式 `n_fmadd_ps` 未覆盖的模式。

### 8.5 C12 后续优化方向（按收益/风险排序）

1. **先修基准噪声（必做）**：否则任何微调都不可验证。
2. **循环上界常量提升**：`while(j<16)` 的 `n_set1_epi32(16)` 每轮被 clang 重广播成 `vpbroadcastd 15`，在生成器把该常量提升到循环外可再省 ~1 条/轮（~5%）。
3. **分支数收敛 / 循环展开**：AutoSIMD 循环体 3 次 `any_true()`（while 条件 + `if(v<0)` + `if(v>50)`）对应 3 个分支 vs ISPC 2 个；改 `GenerateWhileStatement` 掩码/退出结构，或 2x 展开（§四 方向3），收益 ~10%、风险中。
4. **运行时 profile**：VTune 本机不可用；可用 `llvm-mca` 对 Auto/ISPC 两条循环体做静态吞吐对比替代 VTune。

### 10.1 FZ 容差修正 + 13 ULP 根治（S34b-a）

**13 ULP 根因**（用户质疑 SLEEF 精度后重新调查，ulp_probe 最小复现）：
- 失败输入 `src=1.76287103` 走**纯算术分支**（`(a*a-3)/a`），无数学函数——非 SLEEF 误差
- clang-cl 默认 `fp-contract=on` 把 `a*a-3` 自动融合为 fmsub（单次舍入 0x3D7A45AF）；
  C# JIT 严格两次舍入（0x3D7A45A2）——a²≈3.1077 的 ULP（2.4e-7）比结果 r≈0.0611 的
  ULP（3.7e-9）大 64 倍，两次舍入保留 a² 大粒度误差经除法放大到 13 ULP；fused 版反而更精确

**修复**：`NativeTranspiledPrecise` 编译选项改为 `/clang:-ffp-contract=off`（clang-cl 正确
语法；原裸 `-ffp-contract=fast` 被忽略无效）。**自动融合禁用 → 算术分支 bit-exact**；
**显式 `n_fmadd_ps`（§八 增量 9）为 intrinsic 不受影响**——性能无回退（C06 Auto/ISPC=0.93x 持平）。
FZ 容差：FZ5 0→1（FMA 1 ULP）、FZ1 8→16→**8**（13 ULP 根治后仅剩数学分支 SLEEF vs libm ~3.5 ULP）。

### 10.2 C12 循环上界常量提升（S34b-b）

`SimdLoopGenerator.GenerateWhileStatement` 新增 `HoistConditionBroadcastConstants`：
while-true 循环条件中的 `n_set1_epi32/ps(字面量)` 提升为循环外构造的 `simd_value __bound_*`
（直接初始化规避 explicit 构造），循环内复用寄存器——消除 clang 每轮 `vpbroadcastd` 重广播（省 ~1 条/轮）。
生成代码验证：C12 循环体 `n_set1_epi32` 消失。

### 10.3 C12 分支收敛（S34b-c，性能 -22%）

`SimdControlFlowGenerator` 三处修改，每轮 **3 any_true/3 分支 → 2 any_true/2 分支**（对齐 ISPC 2 vmovmskps/2 je）：
1. **continue mask 化**：`GenerateContinueStatement`（while-true）不再 `goto continue`，
   改为 `BodyMaskVar &= ~cond`——后续语句照常执行但 mask 空（无副作用）
2. **break 立即检查删除**：`GenerateBreakStatement` 删除「tracker 空则 goto exit」——
   下一轮循环头 `wm = wcond & tracker; if (!wm.any_true()) break` 自然退出（语义等价）
3. **if 守卫消除**：`HasControlFlowGoto` 加 `maskContinue` 参数——while-true 内已 mask 化的
   continue 不计入 goto 判定 → continue 结尾的 if 不再生成 any_true 守卫（无条件执行 blend）

**实测**：C12 AutoSIMD 0.498→**0.388ms（-22%）**、Auto/ISPC 0.74x→**0.88x**（差距收窄 46%）。
